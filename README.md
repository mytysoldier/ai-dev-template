# ai-dev-template

GitHub Issueを作業単位に、Codexと人が個人開発を進めるためのテンプレートです。初期リリースの範囲を絞り、公開可能な最小構成を優先します。エージェントの詳細な作業ルールは [AGENTS.md](AGENTS.md) を参照してください。

## 新しいリポジトリの初期設定

1. GitHubのテンプレート機能から新しいリポジトリを作成し、クローンする。
2. [初期リリース計画](docs/planning-template.md) をコピーしてプロジェクト用の計画を書き、目的、初期リリースの範囲とスコープ外、技術・保存・公開方針を決める。例示項目はプロジェクトに合わせて変更する。
3. READMEをプロジェクトの説明、起動方法、検証コマンド、公開方法に書き換える。`AGENTS.md` にはプロジェクト固有の構成、制約、検証コマンドや計画の場所を追記し、共通ルールと矛盾しないようにする。未決定の項目は未決定と明記する。
4. 採用した技術に合わせてlint・型チェック・テスト・buildなど適用可能な検証を決め、GitHub Actionsと必要なブランチ保護を各リポジトリで設定する。付属のCIはテンプレートのリンクとIssue記入欄を確認する。アプリの検証は別途追加する。[Codexのコードレビュー設定](https://chatgpt.com/settings/code-review)でリポジトリを接続し、必要に応じて自動レビューを有効にする。
5. 設計Issueを作成し、決定事項から小さな実装Issueに分解する。Issueテンプレートのラベルは各リポジトリに合わせて作成・変更する。

## IssueをCodexに渡す

新しいリポジトリをCodexで開き、例えば `Issue #12 を AGENTS.md に従って対応して` と依頼する。CodexはIssueの確認からPR作成まで進める。GitHubやGitの認証、権限、Codexの実行環境は事前に利用可能にしておく。Issueを作成しただけでは自動実行されない。

PRレビューは、設定済みの自動レビューを使うか、PRのコメントで `@codex review` を依頼する。反応がない場合はリポジトリ接続とコードレビュー設定を確認する。

## 開発の流れと役割

1. **企画・設計**: 人が目的や制約を伝え、設計Issueで初期リリースの範囲、作らないこと、技術・保存・公開方針を整理する。Codexは設計Issueで実装コードを書かない。仕様や方針の決定は人が確認する。
2. **Issue化**: 実装Issueには目的、範囲、観測可能な受け入れ条件、スコープ外、依存Issue、検証方法を書く。依存がない場合は「なし」、未決定なら「未定」と書き、依存先は `#番号` で示す。検証はコマンドや操作と期待結果を具体的に書く。
3. **着手**: Codexは対象Issueと直接の依存IssueのGitHub上の状態、関連資料、オープンPR、変更箇所を確認する。安全に並列化できる場合は対象と理由・競合しない前提を伝え、Issueごとに別セッション・ブランチを用意する。依存や競合がある場合は直列に進める。
4. **実装・PR**: CodexはIssueの範囲で実装・検証し、結果を記録してコミット、push、Open PRを作成する。PRはIssueに紐付け、実行した検証と未実施の理由を記載する。
5. **レビュー**: GitHub Actionsの結果、CodexのPRレビュー、人の確認を組み合わせる。Codexは明確な指摘やCI失敗を最小差分で修正し、再検証・push・PRへの対応コメントを行う。仕様変更、スコープ拡大、方針が曖昧な指摘は人に判断を求める。人が最終的に確認し、マージを判断する。
6. **マージ後**: PRの `MERGED` を確認し、未コミット変更を保護したうえで `main` をfast-forward更新し、そのPRの作業ブランチだけを整理する。具体的な手順は [AGENTS.md](AGENTS.md) に従う。

Issueと既存資料から安全に決められる実装上の選択はCodexが進めます。仕様・スコープや技術スタック、提供形態、保存方式の変更が必要な場合は、理由と影響を伝え、人の判断を受けてから進めます。GeminiやAntigravityは調査や別案比較の補助として利用できます。

## 共通の検証

`python3 scripts/verify.py` でテンプレートのリンクとIssueテンプレートの基本項目を確認できる。PRとmainへのpushでもGitHub Actionsが同じ確認を実行する。プロジェクト固有のテスト・buildは別途設定し、`AGENTS.md` にコマンドを記載する。
